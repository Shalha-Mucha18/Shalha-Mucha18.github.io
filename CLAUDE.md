# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Branch model — read this first

This repository has two purposes split across two long-lived branches:

- **`main`** — the Jekyll **source** (al-folio theme). All edits to content, layouts, styles, plugins, or config happen here.
- **`gh-pages`** — the **built static output** that GitHub Pages serves. This branch is generated by CI (`.github/workflows/deploy.yml`) from `main`. **Do not hand-edit files on `gh-pages`** — your changes will be overwritten on the next deploy.

If the working tree is on `gh-pages` and the user asks for an edit, they almost certainly mean the source. Switch to `main` (or inspect `origin/main`) before editing. The presence of `Gemfile`, `_config.yml`, `_layouts/`, `_plugins/`, `_includes/`, and `_sass/` is the marker for a source checkout.

## Common commands (run on `main`)

Local dev is via Docker (the legacy local Ruby setup is no longer supported by upstream):

```bash
docker compose pull && docker compose up   # serves at http://localhost:8080 with live reload
docker compose -f docker-compose-slim.yml up   # slim image alternative
docker compose up --build                   # rebuild image after Gemfile changes
```

Deploy is automatic on push to `main` via GitHub Actions. Manual deploy script: `bin/deploy` (pushes a built `gh-pages` from `main`).

Formatting / linting (enforced in CI):

- **Prettier** — `.github/workflows/prettier.yml` and `prettier-html.yml` check formatting on PRs. Configured by `.prettierrc` / `.prettierignore`.
- **pre-commit** — `.pre-commit-config.yaml` runs trailing-whitespace, end-of-file-fixer, check-yaml, check-added-large-files. Install hooks once with `pre-commit install`.
- Other CI: CodeQL, axe accessibility, broken-link checks, lighthouse-badger, TOC updates.

## Architecture notes

This is a **content-driven Jekyll site** — there is no application logic. Productive edits almost always mean changing one of:

- `_config.yml` — site-wide settings: identity (`first_name`, `last_name`), `url`/`baseurl`, navbar, search, scholar/bibliography options, plugin config. Most "the site behaves differently" requests are config changes, not code changes.
- `_pages/*.md` — top-level pages (`about.md`, `projects.md`, `publications.md`, `cv.md`, `news.md`, `repositories.md`, `books.md`, `teaching.md`, `blog.md`, `dropdown.md`). Each page declares its `layout:` and `permalink:` in front matter.
- `_data/` — structured content consumed by layouts (e.g. CV sections, social links, repositories list). Edit here rather than hard-coding into layouts.
- `_news/`, `_posts/`, `_projects/`, `_books/`, `_bibliography/papers.bib` — collections rendered by their respective pages.
- `_layouts/*.liquid` — page templates (`about`, `page`, `post`, `cv`, `bib`, `distill`, `book-shelf`, `book-review`, `archive`, `default`, `none`). Pages reference these via `layout:` front matter.
- `_includes/` — reusable Liquid partials.
- `_sass/` + `assets/css/` — styling.
- `_plugins/*.rb` — custom Jekyll plugins (cache-bust, external-posts, scholar/inspirehep citation fetchers, hide-custom-bibtex, file-exists, details block, download-3rd-party assets, remove-accents). When something odd happens at build time, look here before assuming a gem bug.

The build pipeline: Jekyll reads `_config.yml`, runs the gems listed in `Gemfile`'s `:jekyll_plugins` group (notably `jekyll-scholar` for `.bib` rendering, `jekyll-archives-v2` for tag/category pages, `jekyll-paginate-v2` for blog pagination, `jekyll-jupyter-notebook` for `.ipynb` posts, `jekyll-imagemagick` for responsive images, `jekyll-minifier`/`jekyll-terser` for output compression). Custom `_plugins/` run alongside. Output is written to `_site/` locally and to the `gh-pages` branch in CI.

## Editing conventions

- When adding a project, news item, or post, create a new file in the matching collection directory (`_projects/`, `_news/`, `_posts/`) — do not edit the index page directly; the layout iterates the collection.
- Bibliography entries go in `_bibliography/papers.bib`; `publications.md` renders them via `jekyll-scholar`.
- The `baseurl` setting in `_config.yml` affects all internal links — for a user/org page (`<user>.github.io`) it must be empty (`baseurl:`), not `/al-folio`.
- Upstream theme docs that ship in-repo and are worth consulting: `INSTALL.md`, `CUSTOMIZE.md`, `FAQ.md`, `CONTRIBUTING.md`.
